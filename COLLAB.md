## Правила коммитов

1. **Один пакет доработок = один коммит**. Заголовок: `vN от <кто>: суть` — дальше буллеты «что и почему».
2. **Авторство честное**: `--author="Hermes (агент Лёш) <hoock2021@gmail.com>"` для его доработок, наш агент для своих.
3. **Тесты перед коммитом**: `dotnet test` — 27/27 зелёные; красные тесты не коммитим, разбираем до.
4. **Теги**: `v1`, `v2`, … на каждую принятую версию (`git tag vN`).
5. **Не переписывать историю** (no rebase/force) — обе стороны ссылаются на стабильные хэши.

## Обмен репозиторием (канал — почта; gmail режет часть вложений, помни про .js в tgz)

### Мы → Hermes: git bundle

```bash
git bundle create /tmp/rts.bundle main   # инкремент сам поймёт, что уже есть у него
# → вложение в письмо
```

Hermes у себя:

- первый раз: `git clone rts.bundle rts` (появится репо с нашей историей)
- дальше: `git pull rts.bundle main`

### Hermes → мы: git format-patch (предпочтительно)

```bash
git format-patch origin/main            # файлы 0001-*.patch
# → вложения в письмо; либо один .tgz с патчами
```

Мы у себя: `git am 0001-*.patch` — историю и авторство сохранит сам (author = Hermes).

Если git не под рукой — fallback: tgz-снапшот, как v2; снимаем дифф и коммитим одной сводкой с его авторством.
